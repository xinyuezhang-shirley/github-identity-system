# github-identity-system

A GitHub profile identity system that extends the visual language already
built and working in two sibling projects — **MuseLab** and **Echo** —
instead of inventing a new one. Those two projects aren't references;
they're treated here as the design system itself, calibrated as two
themes: MuseLab's paper/editorial mode for light, Echo's
instrument/computation mode for dark. See
[`docs/design-dna.md`](docs/design-dna.md) for exactly what was extracted
and where each rule comes from in the source code.

**Status:** concepting → prototyping. Four of five identity directions
have a working prototype. No direction has been chosen as the final
README yet — this repo is the workspace that decision gets made in.

## Structure

```
github-identity-system/
├── README.md                    this file
├── docs/
│   ├── design-dna.md            9 strands modeled as rules, + generative rules + anti-patterns
│   ├── identity-directions.md   5 named directions, scored against MuseLab's disliked_patterns.md
│   ├── visualization-ideas.md   10 ideas for turning GitHub metadata into diagrams
│   ├── information-architecture.md   section-by-section outlines for 3 directions
│   └── mockups/                 static SVG exports + links to live prototypes
├── prototypes/                  one working HTML page per identity direction
│   ├── folio/                   Direction C — numbered dossier index
│   ├── instrument/               Direction B — live commit signal trace + readout
│   ├── topology/                 Direction D — live polar language field
│   └── ledger/                   Direction E — dated, itemized repo table
├── assets/
│   ├── tokens.css               the calibrated light(MuseLab)/dark(Echo) design tokens — single source of truth
│   ├── typography/               self-hosted woff2 fonts + fontfaces.css
│   ├── js/                       vortex-field.js, theme-colors.js, reveal.js — ported from Echo/MuseLab, not reinvented
│   ├── diagrams/                 static SVG exports, generated by scripts/build_diagrams.py
│   └── generated/                real GitHub data snapshots (languages, commits, repos), generated by scripts/fetch_github_data.py
└── scripts/
    ├── fetch_github_data.py      pulls live data via `gh api graphql`
    └── build_diagrams.py         turns that data into the SVGs in assets/diagrams/
```

## Running the prototypes

The prototypes fetch JSON from `assets/generated/` at runtime, which most
browsers block under `file://`. Serve the repo root over HTTP:

```bash
python3 -m http.server 8000
# then open http://localhost:8000/prototypes/folio/
#           http://localhost:8000/prototypes/instrument/
#           http://localhost:8000/prototypes/topology/
#           http://localhost:8000/prototypes/ledger/
```

Toggle your browser/OS theme to switch between MuseLab's light calibration
and Echo's dark one — the tokens are designed to make that swap the
argument, not a color inversion. See `docs/design-dna.md`, Strand 06.

## Refreshing the data

```bash
python3 scripts/fetch_github_data.py xinyuezhang-shirley   # requires `gh auth login`
python3 scripts/build_diagrams.py
```

Both scripts are idempotent and safe to re-run; they overwrite their own
output files in `assets/generated/` and `assets/diagrams/` only.

## Where this came from

The design DNA in `docs/` was extracted directly from source in two
sibling project directories (not included in this repo):

- `MuseLab/` — see especially `design-memory/taste_profile.md`,
  `design-memory/disliked_patterns.md`, `frontend/src/index.css`, and the
  `frontend/src/lib/imprint/` canvas adapters
- `echo/` — see especially `frontend/styles.css` and
  `frontend/helperJS/vortex.js`
