# Design DNA

Nine strands, modeled as rules — not a mood description. Each strand is a
function you could actually call, extracted from working code in
`MuseLab/` and `echo/`, not read off a screenshot. Two closing entries —
Generative Rules and Anti-patterns — compile the strands into reusable
functions and named failure modes.

Source files cited below are paths inside the sibling `MuseLab/` and
`echo/` project directories, not inside this repo.

---

## Strand 01 — Typography DNA

A five-role stack, never mixed within a role: **Cormorant Garamond**
carries display and mastheads, **Literata** carries reading prose and
italicized voice-over, **IBM Plex Mono** carries every label/index/gutter,
**Courier Prime** carries typewriter residue, **Caveat** carries the rare
handwritten tether — used at under 5% of any surface.

The scale relationship is not a smooth type ramp. It's one extreme jump: a
9–11px tracked mono label sits directly beside a display headline that can
run to 14vw. The label doesn't shrink to match the headline's importance —
it stays tiny and lets tracking carry its authority.

```
label-size      9–11px, tracking 0.16–0.38em, uppercase
display-size    clamp(1.9rem, 6vw, 4.1rem) — or up to 14vw on a true masthead
ratio           label:display font-size ≈ 1:6, held constant across both codebases
```

## Strand 02 — Spatial DNA

The hairline rule (1px, full or near-full measure) is the only structural
divider that exists. There is no card, no shadow, no rounded container
anywhere in either codebase — boundaries are drawn, not implied by
elevation.

Desktop space is explicitly not a single vertical scroll. MuseLab's own
decision log (`design-memory/DESIGN_DECISION_LOG.md`) rejected "a single
towering column when the workshop model calls for juxtaposed corridors,
grids, or spatial navigation." Space is claimed in width, not just depth.

## Strand 03 — Diagram DNA

Every diagram answers `taste_profile.md`'s own five-question test before
it's allowed to exist: what does this mark encode right now, what
relationship does it make legible, what disappears if it's removed, does
it steer toward evidence, is it evidenced or garnish.

A consequence that shows up everywhere: the label *is* the node. Words sit
directly on the coordinate system (`vortex.js`, `orbit.js`, the semantic
graph) — there is no icon standing in for a word, no legend translating a
shape back into English.

## Strand 04 — Mathematical DNA

The generative core of both apps is polar placement where distance from
center is an inverse function of importance — the words that matter most
sit closest to the center, everything peripheral drifts outward. This
single rule produces the vortex spiral, the orbit rings, and
(structurally) the manuscript gutter's emphasis logic.

```
vortex.js — spiral placement
angle  = index × 0.42
radius = 18 + index × spiralStep + (1 − semanticScore) × outerSpread

orbit.js — ring placement (≤3 concentric bands)
radius = minR + (maxR − minR) × (innerBand + ringT × bandWidth)
angle  = (slot / slotsInRing) × 2π + ringIndex × 0.45

both: importance ↓ ⇒ radius ↓ — never the reverse
```

See `assets/diagrams/mathematical-spiral-proof.svg`, generated by
`scripts/build_diagrams.py` from this exact formula (26 points, no
hand-placement).

## Strand 05 — Motion DNA

All continuous motion is exponential smoothing toward a target —
`view.scale`, offsets, particle wobble all use the same one-line damping
rule. There is no spring physics and no overshoot anywhere in either
codebase.

```
every frame: value += (target − value) × k,   k ≈ 0.14
```

The discrete-transition easing curve decelerates and never bounces:
`cubic-bezier(0.22, 1, 0.36, 1)`, named literally `easeArchival` in the
source.

See `assets/diagrams/motion-settle-curve.svg` — the literal 60-frame
iteration at k = 0.14, monotonic, no bounce. An earlier draft of this
diagram plotted a damped cosine (invented oscillation); the real formula
has no oscillation term, so that draft was wrong, not just under-designed.

## Strand 06 — Color DNA (two studios, not one inverted palette)

MuseLab and Echo are not the same palette in two states. **MuseLab**
carries a ferric-brass accent (`#8b6914`) through a warm cream gradient
body, in both its own paper and night modes. **Echo**, independently,
carries no accent hue at all — its `styles.css` is pure neutral (`#000` /
`#f5f5f5` / `#888`), with a body-class toggle between true black and a
cooler paper.

This project's light theme is MuseLab's real tokens, verbatim. Its dark
theme is Echo's real tokens, verbatim — flat black, no gradient, no grain
(Echo's `styles.css` has none), body copy set to mono instead of serif
(Echo's own `body { font-family: var(--mono); }` rule). The accent
survives into dark mode only as a whisper, because Echo doesn't really
have one.

```
light = MuseLab, verbatim
  --bg #f4efe6…#e8dfd2 gradient   --accent #8b6914   --font-running Literata

dark = Echo, verbatim
  --bg #000, flat, no gradient    --accent none (whispered)   --font-running IBM Plex Mono
```

See `assets/tokens.css` for the implementation — one file, both
calibrations, referenced by every prototype in this repo.

## Strand 07 — Composition DNA

"Controlled chaos" as written in `taste_profile.md`: asymmetry,
interruption, and handwritten intrusion are welcomed — but only on top of
a grid that stays legible underneath. The chaos is a layer, never the
foundation.

Roman-numeral or letter-index markers (`I · vortex`, `II · soup`) don't
just label sections — they assert that the sections form a real, ordered
sequence, and the design log treats an index that doesn't correspond to a
real order as false precision.

> "nothing should feel arbitrary" — `disliked_patterns.md`, verbatim

## Strand 08 — Interaction DNA

Every interactive surface exposes its own physics as sliders
(density / motion / intensity) — the system is honest about being
parametric rather than a fixed illustration wearing the costume of an
illustration.

Interaction is metaphored as handling a physical object: drag uses
grab/grabbing cursors with no artificial inertia, wheel-zoom is anchored
to the cursor point like a loupe, double-click resets — never a
UI-control metaphor (no toggle switches, no buttons that light up).

## Strand 09 — Information Architecture DNA

Content is a dossier of named folio sheets you move between at your own
pace, not a chat thread or an infinite scroll. Each sheet has a short code
and a sub-label, mirroring how a physical archive box is labeled.

Argument structure is explicit and reused verbatim as layout order:
**Evidence → Pattern → Interpretation → Claim → Revision question**. The
reasoning chain is made visible as the actual sequence of blocks on the
page, not just as an internal process.

## Generative Rules

Five functions, extracted once, reusable on any new surface:

1. `place(item, i, n) → (θ, r)` — angle by index-step, radius inverse to importance
2. `emphasis(item) → opacity` — continuous function of a real score, never a binary switch
3. `label(block) → eyebrow` — every content block gets a tracked micro-label before its headline
4. `mark(token, category) → style` — underline/italic/weight keyed to a real category, always with a legend
5. `ease(current, target, k) → next` — exponential settle, applied to anything that moves

`assets/js/vortex-field.js` and `assets/js/theme-colors.js` implement
rules 1, 2, and 5 as a reusable module — see the prototypes for usage.

## Anti-patterns

Named directly in `disliked_patterns.md`, and worth restating because a
GitHub-facing identity system will be tempted by all of them:

- Ornament with no encoded referent ("floating shapes with no structural role")
- Dialect drift where each surface invents its own palette
- Fake depth via drop-shadows or stacked card strata standing in for real information layering
- Diagram cosplay — a force graph or hub-and-spoke whose edges don't correspond to a real relationship
- More than one accent hue; gradients as decoration; glassmorphism; rounded-xl corners
- Redundant restatement across elements
- Sterile, generic "clean UI" that deletes meaning along with clutter — **"cleaner but worse" is a valid verdict in MuseLab's own review process.**
